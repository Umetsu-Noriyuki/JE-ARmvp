# AR共有アプリ 検証用MVP 基本機能仕様書

## 1. 目的

スマートフォンのカメラ映像に対して、ユーザーが文字・図形・簡単な画像等のARオブジェクトを配置し、その位置情報を保存する。

保存したARオブジェクトを他のユーザーと共有し、共有されたユーザーが同じ場所を訪れた際に、現実のカメラ映像上にARオブジェクトを表示できることを検証する。

本MVPでは、以下を主要な検証項目とする。

1. スマートフォン上でARオブジェクトを現実空間に配置できるか
2. 配置したARオブジェクトを保存・再表示できるか
3. 別ユーザーの端末から同じARオブジェクトを取得できるか
4. 別ユーザーが同じ場所でARオブジェクトを現実空間上に再表示できるか
5. ユーザーが「ARオブジェクトを誰かに残す」という体験に価値を感じるか

# 4. ARオブジェクトの基本操作

ユーザーはカメラ画面を見ながらARオブジェクトを作成する。

## 4.1 作成

「ARを作成」を選択するとカメラ画面を表示する。

ユーザーは以下を実行できる。

1. オブジェクト種類を選択
2. 内容を入力
3. カメラ映像上の配置位置を指定
4. 大きさを変更
5. 向きを変更
6. 配置を確定

---

## 4.2 文字オブジェクト

文字入力例：

> ここに集合！

設定項目：

* 文字列
* 文字サイズ
* 文字色
* 背景色
* 水平方向
* 垂直方向

MVPでは装飾機能を最小限とする。

---

## 4.3 図形オブジェクト

最低限、以下を対象とする。

* 円
* 四角形
* 矢印

例：

「この方向」

という案内をAR上に表示する。

# 5. AR配置

## 5.1 配置方法

カメラ映像中の平面を認識し、その平面上にARオブジェクトを配置する。

基本的にはスマートフォンのAR機能を利用する。

想定：

* Android：ARCore
* iOS：ARKit

Flutterアプリから利用する場合は、採用するARライブラリの仕様に合わせて実装する。

---

## 5.2 配置情報

ARオブジェクトには以下の情報を保持する。

| 項目          | 内容         |
| ----------- | ---------- |
| objectId    | オブジェクトID   |
| ownerId     | 作成ユーザーID   |
| type        | オブジェクト種類   |
| content     | 文字・画像等     |
| position    | AR空間上の位置   |
| rotation    | 回転         |
| scale       | 大きさ        |
| latitude    | GPS緯度      |
| longitude   | GPS経度      |
| createdAt   | 作成日時       |
| expiresAt   | 有効期限       |
| shareStatus | 非共有/共有中/終了 |

# 6. 位置情報

MVPでは、AR空間の位置情報とGPS位置情報を分けて管理する。

## 6.1 GPS位置

ARオブジェクトを作成した地点の位置を記録する。

例：

```text
latitude: 37.xxxxx
longitude: 140.xxxxx
```

GPSは「どの場所のARか」を判定するために使用する。

---

## 6.2 AR空間位置

GPSだけでは、建物内のどの場所にオブジェクトを置いたかを正確に再現できない。

そのため、

* AR空間上の座標
* カメラ姿勢
* 必要なARアンカー情報

などを保存する。

---

# 7. ARオブジェクトの保存

ユーザーが「保存」を実行すると、ARオブジェクトを端末内に保存する。

端末内には以下を保存する。

```text
AR Object
 ├─ オブジェクト内容
 ├─ GPS位置
 ├─ AR配置情報
 ├─ 作成日時
 └─ 共有状態
```

MVPでは、**共有していないARオブジェクトはクラウドに保存しない**。

これにより、ARを試すだけの利用ではAWSコストを抑える。

---

# 8. 自分のAR一覧

「マイAR」画面を提供する。

一覧には以下を表示する。

* サムネイル
* オブジェクト内容
* 作成日時
* 作成場所
* 共有状態
* 有効期限

例：

```text
│ 公園入口             │

```

# 9. 共有機能

MVPでは「特定ユーザーへの共有」のみ実装する。

## 9.1 共有開始

ユーザーがARオブジェクトを選択し、

「共有する」

を選択する。

共有時にサーバーへAR情報を登録する。

---

## 9.2 共有対象

MVPでは、共有先を指定する。

方法は以下のいずれかとする。

### 案A：共有コード

共有時に、

```text
ABC123
```

のようなコードを発行する。

受信者がコードを入力すると共有される。

### 案B：URL / ディープリンク

共有時に、

```text
AR共有リンク
```

を生成する。

受信者がリンクを開くとアプリを起動する。

MVPでは、実装が簡単な**共有コード方式を優先**する。

---

# 10. 共有データ

共有開始時に、クラウドへ以下を保存する。

```text
SharedARObject
 ├─ shareId
 ├─ ownerId
 ├─ objectData
 ├─ latitude
 ├─ longitude
 ├─ AR anchor information
 ├─ createdAt
 └─ expiresAt
```

---

# 11. 共有期限

MVPでは、

**共有開始から24時間**

を有効期限とする。

例：

```text
共有開始
2026/09/30 10:00

↓

共有終了
2026/10/01 10:00
```

期限を過ぎたARは取得・表示できない。

---

# 12. 共有ARの取得

受信者は、

「共有コードを入力」

から共有コードを入力する。

サーバーで以下を確認する。

1. shareIdが存在する
2. 有効期限内である
3. 共有状態が有効である

条件を満たした場合、AR情報を端末へ取得する。

---

# 13. 現地でのAR表示

共有ARを取得したユーザーが対象地点へ移動する。

アプリはGPS位置を確認する。

対象地点から一定距離以内に入った場合、

「この場所に共有ARがあります」

と表示する。

ユーザーが「ARを見る」を選択するとカメラを起動する。

# 14. AR位置合わせ

MVPでは、AR位置合わせについて以下の段階で実装する。

## MVP-1

GPSによって対象地点を特定する。

その後、ARCore / ARKitの空間認識を利用して、対象物を配置する。

ただし、別端末間で完全に同じ位置へ自動配置できることは保証しない。

---

## MVP-2

実証結果を見て、

* 画像認識
* 空間特徴点
* Geospatial API
* Cloud Anchor相当の仕組み

などを検討する。

ここは本サービスの技術的な重要ポイントとして別途検証する。

---

# 15. 共有終了

24時間経過後は共有ARを利用できなくする。

端末に保存された元データについては、作成者が削除するまで保持してもよい。

つまり、

```text
自分のAR
    ↓
端末に保存
    ↓
共有
    ↓
クラウドに24時間保存
    ↓
共有期限終了
    ↓
クラウド上の共有データ削除
```

という構成とする。

---

# 16. 削除

ユーザーは自分のARオブジェクトを削除できる。

削除対象：

* 端末内データ
* 共有中の場合はクラウド上の共有データ

共有中のARを削除した場合、共有先ユーザーからも利用できなくなる。

必要に応じて、

```text

```

# 21. 期限切れ処理

DynamoDBのTTLを利用して、期限切れデータを自動削除する。

ただし、TTLは「指定時刻に必ず即時削除される」ことを前提にしない。

そのためAPI側でも、

```text
expiresAt < 現在時刻
```

の場合は取得不可とする。

つまり、

**論理的な期限切れ判定 + DynamoDB TTLによる物理削除**

の2段構成とする。

# 30. MVP開発上の重要事項

このMVPでは、**「完璧なAR位置合わせ」を最初から実現しようとしない**。

最初に検証すべきなのは、

> 「現実の場所にARを残し、別の人が後からその場所で見る」

という体験そのものに価値があるかどうかである。

そのため、

```text
AR表現
  ↓
位置情報
  ↓
共有
  ↓
現地表示
```

という最小構成を完成させることを優先する。

一方、別端末でのAR位置合わせ精度は、このサービスの技術的な最大リスクの一つであるため、Phase 1～3で早期に検証する。

# 32. MVPの基本方針

本MVPでは、

**「無料・限定共有・24時間」**

に限定する。

公開機能や課金機能を先に作るのではなく、

> ARを作る
> ↓
> 誰かに共有する
> ↓
> 相手が現地へ行く
> ↓
> ARを見る

という一連の体験を成立させる。

この体験が成立し、継続利用されることを確認した後に、課金・公開共有・モデレーション・公開スポット管理を追加する。
